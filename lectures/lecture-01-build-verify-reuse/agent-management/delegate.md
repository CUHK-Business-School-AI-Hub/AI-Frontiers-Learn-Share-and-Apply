## Procedures

1. Read inputs/assignment.md and the templates afresh. Identify the requested episode and speaker, the required channels, and destination details. Do not assume that the latest event on a website is the requested one.
2. Retrieve the matching event from the specified source. Record the speaker, affiliation, full title, research description, moderator, date, time zone, and event links in the run file with their sources and access date. Put the verified comparison values in the `## Expected facts` table specified by evaluate.md. Use any verified local facts or explicit corrections supplied in inputs/ as directed. Flag unresolved conflicts rather than silently choosing a value. Do not derive expected facts from the drafts being checked.
3. If the website is unavailable, use sufficient source material supplied in inputs/. Otherwise identify the missing required information and ask for it while returning useful draft work. Do not substitute historical template facts.
4. Draft all three messages, preserving each template's tone, structure, and level of detail. Save the current versions under `## LinkedIn`, `## INFORMS`, and `## Email` in the run file. Adapt the research description faithfully. Keep an optional calendar or series link only when supported for its intended use. Record its exact target under `Allowed links` in the expected-facts table after verifying it, including the event details encoded in calendar links. Omit unconfirmed optional links and note that omission in the run record.
5. Apply learned procedures below, then use evaluate.md and coach.md to check and improve the messages before entering them into the accounts. Run the included checker and resolve or explicitly assess its findings. Its results cover mechanical comparisons only. Preserve the source templates and input data.
6. Use the computer-use tool to operate the browser or apps in Philip's existing signed-in sessions. Confirm the active account and the destinations against inputs/assignment.md. If sign-in, account selection, or access is blocked, ask Philip to resolve it and continue any independent work.
7. Fill the live drafts as follows. Preparing text only in the run file does not complete this step.

   | Account | Required action before human review |
   |---|---|
   | Personal LinkedIn | Open the group specified in inputs/assignment.md, open its post composer, and fill in the complete LinkedIn promotion. Leave it unpublished. |
   | Personal INFORMS | Open every community listed in inputs/assignment.md. Fill the subject/title and message body in each community's post composer. Keep a separate unposted draft or open composer for each destination. |
   | Personal Outlook | Open the email list referenced in inputs/assignment.md and read the intended recipients. Create an email draft with the recipient fields, specified Cc addresses, subject, and full body. Follow any To/Bcc routing instructions in the inputs. If recipient selection or routing is unclear, ask for that detail rather than guessing. Leave the email unsent. |

8. Inspect the filled fields and rendered content in each app with evaluate.md. Correct any entry or formatting errors and recheck the affected drafts. Keep composers open for review, or save drafts where the app supports it without publishing. Record the account, destination, draft location or open tab, and observed status for each item in the run file. Distinguish a saved draft from an open, unsaved composer. If a platform cannot retain a draft, report that limitation and keep the copyable text.

Do not click **Post**, **Send**, **Publish**, **Schedule**, or any equivalent action that distributes the messages. Do not use a keyboard shortcut or another tool to submit them. Stop after filling and checking the drafts, and hand them to Philip for review. Do not overwrite an unrelated existing draft.

In explicit example mode, the selected case brief and problematic drafts replace the current input as the source for assessment. Skip live event retrieval and account interactions. Evaluate those drafts before changing them and keep all exercise outputs local.

INFORMS retains its greeting and cross-posting note. Email retains its subject, greeting, invitation, and organizers' sign-off. Include clear event details and supported links in each message.
